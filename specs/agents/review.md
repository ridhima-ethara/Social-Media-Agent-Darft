# Reviewer — Human edits and compliance

- **Id**: `review`
- **Stage**: `create`
- **Hands off to**: `knowledge`, `publishing`
- **Skills**: 4
- **Handlers**: `server/src/agents/review/handlers.ts`

Applies the operator’s instructions to a draft, runs the twenty-rule compliance check, and extracts durable preferences from what the human asked for. A human instruction always outranks a brand guideline: the edit is applied and the finding is raised alongside it, never resolved silently.

## Skills

### `review.instruction.apply`

Applies what the operator asked for. A human instruction always outranks a brand guideline: the edit is made and the compliance finding is raised alongside it, never resolved silently.

| Knob | Default | Description |
|---|---|---|
| `humanOverridesBrand` | `true` | This is rule 20 and should stay on. Off, the agent refuses instructions that conflict with a guideline instead of applying them and reporting. |
| `maxInstructionChars` | `600` | The ceiling on a single instruction. Longer requests are better split, and the agent says so. |
| `preserveRevisionHistory` | `true` | On, each edit creates a new revision so the earlier draft is still recoverable. Nothing is ever deleted. |

### `review.compliance.check`

Runs the twenty-rule check across grounding, voice, structure, platform, visual and caption-to-visual agreement, and reports a verdict with the evidence.

| Knob | Default | Description |
|---|---|---|
| `offerCorrection` | `true` | On, a purely mechanical set of violations comes with a corrected draft the operator can accept. The correction is never applied automatically. |
| `similarityCap` | `70` | How close a caption may be to something already published before it is held. Repetition erodes the account. |
| `failOnSensitive` | `true` | On, funding, partnerships, named customers, hires, unpublished numbers, legal positions and competitor comparisons force internal approval. This outranks every other verdict. |

### `review.preference.extract`

Notices when an instruction expresses a durable preference rather than a one-off fix, and offers to remember it.

| Knob | Default | Description |
|---|---|---|
| `askBeforeSaving` | `true` | On, the operator is offered the preference and decides. Off, it is written to the Knowledge Base and reported. |
| `minOccurrences` | `2` | How many times a similar instruction must appear before it is treated as a preference rather than a correction. |
| `similarityThreshold` | `60` | How alike two instructions must be to count as the same preference. |

### `review.diff.summarize`

Describes in one line what actually changed between two revisions, so the approval queue shows the edit rather than the whole draft.

| Knob | Default | Description |
|---|---|---|
| `maxChars` | `180` | The ceiling on the change summary shown in the approval hand-off. |
