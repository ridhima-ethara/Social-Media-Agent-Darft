# Knowledge Agent — The cited Knowledge Base

- **Id**: `knowledge`
- **Stage**: `learn`
- **Hands off to**: `caption`, `image`, `calendar`, `review`
- **Skills**: 8
- **Handlers**: `server/src/agents/knowledge/handlers.ts`

The only agent whose primary product is knowledge. Every Sunday at 06:00, and on demand, it researches the top twenty-five hashtags against the live web through Parallel and writes cited, confidence-scored entries. An entry that cannot cite at least two sources is discarded.

## Skills

### `knowledge.hashtag.select`

Takes the current consolidated hashtag set and skips anything researched recently, unless a refresh is forced.

| Knob | Default | Description |
|---|---|---|
| `hashtagCount` | `25` | How many hashtags the build researches. This is the direct driver of both research cost and Knowledge Base coverage. |
| `recencyDays` | `5` | A hashtag researched more recently than this is skipped, so a weekly build does not re-research everything. |
| `forceRefresh` | `false` | On, everything is re-researched regardless of when it was last done. Useful after a positioning change. |

### `knowledge.research.search`

The Parallel call. Asks what is materially new about each hashtag in the recent window, demanding concrete findings, named sources, dates and figures, and excluding vendor marketing.

| Knob | Default | Description |
|---|---|---|
| `maxParallel` | `4` | How many hashtags are researched at once. Higher finishes sooner and is more likely to hit a rate limit. |
| `windowDays` | `14` | How recent a finding must be to count as materially new. |
| `processor` | `base` | Base is fast and adequate for weekly coverage. Pro and ultra read more sources per hashtag and cost proportionally more. |
| `maxResults` | `10` | How many web sources to read for each hashtag. |
| `retries` | `2` | How many times a failed research call is retried before that hashtag falls through to the open-web reading. |

### `knowledge.research.extract`

Turns raw research into candidate entries with their citations, and discards anything that cannot cite enough independent sources. An uncited claim never enters the Knowledge Base.

| Knob | Default | Description |
|---|---|---|
| `minSources` | `2` | An entry citing fewer independent URLs than this is discarded. Two is the floor at which a claim is worth keeping. |
| `maxChars` | `900` | The ceiling on an entry body. Entries are read by the caption writer, so they must stay dense. |
| `maxEntriesPerHashtag` | `3` | How many entries one hashtag may contribute to a build. |

### `knowledge.entry.upsert`

Compares each candidate against the active entries and merges rather than duplicating, unioning the sources and promoting confidence as evidence accumulates.

| Knob | Default | Description |
|---|---|---|
| `dedupeThreshold` | `72` | How similar a candidate must be to an existing entry to be merged into it instead of inserted alongside. |
| `promoteOnMerge` | `true` | On, an entry confirmed by a second independent source moves up a confidence band. |

### `knowledge.entry.retrieve`

The read path every other agent uses, including the caption writer and the command plane knowledge search tool.

| Knob | Default | Description |
|---|---|---|
| `maxResults` | `12` | How many entries a single retrieval returns. |
| `includeInactive` | `false` | Off, an entry switched off in the Knowledge Base genuinely stops influencing generation. That is the point of the toggle. |

### `knowledge.entry.rank`

Orders retrieved entries by a blend of confidence and topical closeness.

| Knob | Default | Description |
|---|---|---|
| `confidenceWeight` | `55` | How much confidence counts against topical similarity. Higher favours well-evidenced entries over closely-matching ones. |

### `knowledge.conflict.resolve`

Finds entries in the same category that disagree and resolves them by the declared strategy. Escalation writes a real queue row, not a flag.

| Knob | Default | Description |
|---|---|---|
| `strategy` | `Newest wins` | Newest wins suits fast-moving research. Highest confidence wins suits stable ground. Escalate sends every conflict to a person. |
| `conflictSimilarity` | `55` | How similar two entries must be before their disagreement is treated as a conflict rather than two separate facts. |

### `knowledge.priority.tag`

Boosts entries tagged as priority so they are retrieved ahead of the rest, and optionally demotes untagged ones.

| Knob | Default | Description |
|---|---|---|
| `priorityBoost` | `25` | How much a priority-tagged entry is favoured during retrieval. |
| `demoteUntagged` | `true` | On, untagged entries are pushed down so curated ones lead. Off leaves the ordering to confidence and similarity alone. |
